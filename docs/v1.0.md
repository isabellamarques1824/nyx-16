# NYX-16 v1.0

This document defines the scope of NYX-16 version 1.0.

The goal of v1.0 is to provide a complete virtual 16-bit computer capable of loading and executing programs written for the NYX-16 ISA.

Detailed architectural decisions are documented in `architecture.md`.

## v1.0 Requirements

### CPU

The CPU must include:

- 8 general-purpose registers: R0–R7
- Program Counter (PC)
- Instruction Register (IR)
- Stack Pointer (SP)
- Status Register (SR)
- ALU
- Instruction decoder
- Control unit
- running/halted state
- complete fetch-decode-execute cycle

### ALU

The ALU must support:

- ADD
- SUB
- AND
- OR
- XOR
- NOT
- ZERO flag
- NEGATIVE flag
- CARRY flag
- OVERFLOW flag

### ISA

The v1.0 ISA must support:

- NOP
- HALT
- MOV
- LDI
- LOAD
- STORE
- ADD
- SUB
- AND
- OR
- XOR
- NOT
- CMP
- JMP
- JZ
- JNZ
- JN
- PUSH
- POP

Instructions use the fixed two-word encoding defined in `architecture.md`.

### Memory

v1.0 must provide:

- 16-bit addresses
- 65,536 word-addressed memory locations
- unified memory for code and data
- program base at `0x0000`
- heap base at `0x2000`
- stack base at `0xFFFF`
- LOAD and STORE support
- PUSH and POP support

### Program Execution

NYX-16 must be able to:

1. load a machine-code program into memory;
2. fetch instructions using the PC;
3. decode the instruction;
4. execute it;
5. update registers, memory and flags;
6. perform conditional and unconditional jumps;
7. continue execution until HALT.

### Tooling

v1.0 should also include:

- a simple program loader;
- a basic assembler for the NYX-16 ISA;
- unit tests for the main components;
- integration tests;
- small example programs.

## Definition of Done

NYX-16 v1.0 is complete when a program can be written in NYX-16 assembly, converted to machine code, loaded into memory and executed correctly by the virtual CPU until HALT.

## Out of Scope

The following features are not required for v1.0:

- CALL / RET
- MUL / DIV
- floating point
- indirect addressing
- interrupts
- exceptions
- privilege levels
- virtual memory
- cache
- pipeline
- multicore processing
- advanced I/O
- operating system
